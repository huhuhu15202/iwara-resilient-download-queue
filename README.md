# Iwara Resilient Download Queue

本地 Iwara 下载队列与视频台账服务。下载解析由网页脚本完成，稳定下载、失败重试、文件校验、元数据补齐和本地播放由本服务负责。

## 功能

- 最多 3 个并发下载；作者/日期、播放量和标签补齐使用独立的 8 路元数据并发池，失败记录永久保留。
- 使用 Aria2 RPC（可选 FFmpeg 兜底）下载到统一视频目录。
- 本地台账、文件缺失检查、失败重试和作者分类整理。
- 本地播放列表：每页 30 个视频；点击卡片进入独立播放器，避免列表页长期保留播放器资源。手机端顶部不再吸附，滚动接近底部会自动加载下一页，同时保留“加载更多”手动入口。
- 播放列表支持图库式勾选；选中一个本地视频后可直接下载保存（不重新解析、不重复提交任务）。
- 下载目录当前配置为 `J:\Video`；服务会按视频 ID 兼容移动后或作者分类后的文件路径，避免仅因改盘符/改文件名就误报缺失。
- 播放器当前使用浏览器原生 `<video controls>` 控件，交由 Chrome 处理全屏和操作系统级画中画；Plyr 资源暂时保留但不加载。列表页每次从第 1 页打开，并可输入页码跳转。
- 支持通过 Tailscale 等加密组网工具从外部访问；服务会将 `100.64.0.0/10` 范围内的 Tailscale IPv4 地址一并显示为播放入口，不需要把 18777 端口直接暴露到公网。
- 独立播放器只保留当前视频和少量相邻切换项；相邻项使用静态随机帧，不在悬停时播放。
- 播放进度和已看完状态写入台账，支持继续播放；上一部/下一部到达邻居窗口边缘时会按全局排序增量加载，不会卡在 5 个视频上。
- 播放列表支持点击高频标签、卡片标签或作者，立即按标签/作者重载列表；也提供作者下拉筛选。
- 独立播放器提供“仅音频”模式：隐藏视频画面但继续播放声音、保留进度保存和顺序/随机/循环切换。
- 播放失败会区分台账缺失、HTTP 文件错误和浏览器 codec/容器不支持，并给出处理建议。
- 网页嗅探脚本 3.3.126 兼容 Iwara CDN 的 `/view?filename=..._Source.mp4` 地址；这类地址会按真实直链识别，不再无条件等待 45 秒超时，并会把 Iwara 标签带回台账。
- 远程播放模式按需生成 480p H.264/AAC 临时缓存；局域网播放仍直接使用原始视频，不修改原文件，也不把转码文件放进正式下载目录。
- 台账和播放列表提供“更新全部播放量”按钮；它会重新排队所有已下载视频，播放量/标签使用独立的元数据并发池，不占用 3 个下载槽位。
- 台账和播放列表提供“同步缺失标签”和“更新全部标签”按钮；标签会写入 SQLite 台账，也支持搜索和卡片显示。旧导入文件的作者/日期基础资料补齐由 `importedMetadataEnrichmentEnabled` 控制，当前服务默认暂停，避免历史失败任务挤占下载。
- 移动或重新扫描已有文件只重建本地文件引导和路径索引，不会自动访问 Iwara；只有控制面板中的手动同步按钮才会创建远程资料任务。

## 使用

1. 安装 Node.js >= 22.13.0（推荐当前 Node.js 24 LTS）、Aria2（或 Motrix Next）。`node:sqlite` 在 Node 22.5.0 才加入，Node 22.13.0 起无需实验参数。
2. 复制 `config.example.json` 为程序目录下的 `config.json`，按本机目录填写 `dataRoot`、`downloadRoot` 和 `enginePath`；也可以使用 `IWARA_DATA_ROOT`、`IWARA_DOWNLOAD_ROOT`、`IWARA_ENGINE_PATH` 环境变量覆盖。无需修改源码。
3. 双击 `启动稳定下载.cmd`。启动脚本会拒绝低于 Node 22.13.0 的运行时。
4. 打开 `http://127.0.0.1:18777/`，播放列表地址为 `http://127.0.0.1:18777/playlist`。
5. 在 Tampermonkey 中安装 `IwaraResilientQueue.user.js`，并将下载方式指向本地队列。

### 局域网播放

默认仍然只允许本机访问。需要用手机、平板或局域网其他电脑播放时，将 `config.json` 中的 `serviceHost` 改为 `0.0.0.0` 后重启服务。服务会自动生成并保存 `lanAccessToken`，启动日志会输出带令牌的局域网播放链接；也可以在台账首页点击“显示局域网播放链接”。首次打开该链接后，令牌会写入本机 Cookie，之后直接访问 `/playlist` 即可。播放列表为每个视频和封面生成仅限该资源、有效期 12 小时的地址，手机媒体请求不必依赖 Cookie。

台账首页的“显示局域网播放链接”会分别显示普通局域网入口和“远程480p”入口。Tailscale 地址默认使用远程 480p 模式；通过 Cloudflare Tunnel、FRP 等其他入口时，在播放列表地址后加 `?profile=remote` 即可。远程模式第一次打开视频会等待 FFmpeg 生成缓存，随后仍使用 HTTP Range 分段播放并支持拖动。缓存位于 `dataRoot/transcode-cache/480p`，默认最多保留 20 GiB、24 小时，自动清理，不生成 JSON。

局域网令牌同时保护台账和下载管理接口；不要把端口转发到公网，也不要把带令牌的链接发给不可信的人。Windows 防火墙若拦截访问，只允许 18777 端口通过“专用网络”配置文件。

## 测试

`npm test` 会运行状态机、失败分类、媒体格式和文件移动测试；`npm run test:engine` 会实际创建 SQLite 数据库并验证每日 backup 流程。

## 数据与隐私

下载数据库、日志和运行时状态应放在本机数据目录，不要提交到 Git。视频文件也不会随源码发布。公开发布前请检查自己的目录、代理、令牌和浏览器配置。

支持导入并校验 `.mp4`、`.webm`、`.mkv`、`.mov`、`.avi` 和 `.m4v`；本地媒体接口会根据实际扩展名返回对应 MIME 类型。

播放列表会把播放进度、已看完状态保存到台账，支持继续播放、观看状态筛选和上下集切换。视频封面由本机 FFmpeg 按需截帧，只在服务内存中保留最多 150 张，服务关闭即清空，不产生额外封面文件。媒体文件状态也会写入 SQLite 索引，列表请求只读分页结果，不逐条扫描磁盘；服务启动时做一次校验，运行期间按批次后台复核。

## 许可

`IwaraResilientQueue.user.js` 保留上游 Iwara Download Tool 的 Apache-2.0 声明；本地服务部分按仓库维护者的发布范围使用。
