# 新下载自动指纹与 CDN 重试修复

## 本次范围

- 新下载通过媒体完整性检查、文件入库且 SQLite 台账提交成功后，自动排队建立完整 SHA-256 和手机抽样指纹。
- 一个后台工作任务，完整读取限速 32 MiB/s。不会等待哈希才释放下载轮询，也不占用三个下载名额。
- 队列保存在台账的 `mobile_fingerprint_jobs` 表，指纹保存在 `mobile_media_identity` 表。不生成视频旁的 JSON 或副本。
- 关闭时中断哈希，已提交指纹保留；重启接管未完成的队列，并找回“台账提交后、队列插入前关闭”的缺失工作。
- 每个指纹任务最多尝试三次；失败记录在状态接口和服务错误日志中，不把已成功下载的视频改成下载失败。
- 手机同步导出自动包含新指纹及电脑台账的 `completedAt`，不改变已有任务 ID、观看记录或最近下载时间。

## 连续失败证据

查看生产台账发现三个视频 `RcF5lBon6ekkK7`、`DrNlqGaWErmQpC`、`ceXMgumHJMy02d`：先在两个 CDN 上发生约 10 MiB 后的 `No URI available`，之后手动重试只报“所有可用 CDN 源均已失败”，没有开始新的 CDN 下载。

旧 `failedSourceHosts` 从全部历史中排除 CDN，临时错误 `unknown`、握手失败和网络错误也会长期封禁整个域名。现改为仅保留明确证书名称错误的短期源回避；手动重试以事件 ID 建立新会话，不删除历史，也不沿用旧会话的域名排除。

`No URI available` 归为网络/传输问题。保留六次普通尝试和一次嗅探，不降低 TLS 验证，不自动重新下载全部历史失败记录。不能仅由这些日志断言 Iwara 永久失效、作者删除或代理故障。嗅探 45 秒无请求和明确私密视频仍是不同原因。

## 隔离验证

命令：`node --test`（生产视频不参与移动、删除或故障注入）。

新增覆盖：

- 完成入库后自动哈希；完成提交失败不发布工作；手机导出得到指纹和电脑下载时间。
- 新下载与全量扫描交叠，以及先排队再手动扫描，均只有一个工作任务。
- 计算中关闭、重启恢复；已完成身份不重复读取；恢复 finalizing 文件也能自动排队。
- 文件缺失最多三次、失败可报告、不阻塞另一个文件；一次指纹写库失败后可恢复。
- 临时 CDN 错误不封禁两个域名；手动重试保留历史，并持久化新的事件游标。

以上是临时文件和受控下载状态的链路测试，不等同于 Iwara 实际网络下载成功，也不等同于手机实机验证。真实失败记录保持原状态，等待用户选择后重试。
