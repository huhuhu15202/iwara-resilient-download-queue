# Han1me 文件夹自动入账

服务启动后会按 15 秒间隔检查 Han1me 新接收目录。本机 `config.json` 用 `han1meDownloadRoot` 指定新接收/自动入账目录，并用 `han1meHistoryRoots` 列出历史目录。归档上传只写入配置的新接收目录，历史文件不移动、不删除；手机历史去重同步扫描配置的全部目录并合并唯一编号，任一路径不可用时返回错误，不会提交不完整列表。配置的目录都加入手机资料指纹范围。

文件大小和修改时间至少稳定 15 秒、扩展名为 MP4/WEBM/MKV/MOV/AVI/M4V 且大于 64 KiB 后，服务会在配置的数据目录中的 SQLite 台账创建一条已完成记录，随后进入现有播放列表。播放列表/远程播放仍由本地服务提供。若 `mobile_media_identity` 中已有同大小、同采样指纹的文件，服务会再核对完整 SHA-256，确认相同后跳过重复副本，不会按采样指纹直接猜测。

导入时优先读取视频同目录的 `info.json`：使用 `title`（缺失时回退 `chineseTitle`）、`artist.name`、`uploadTime` 和 `tags`；若字段确实不存在，再从文件名或目录名推定标题和作者。数字目录名作为 Han1me 视频 ID（例如 `102355` → `han1meview-102355`），因此与同一视频的既有台账记录保持一致。文件修改时间只用于记录本地入账时间，不冒充上传日期。当前下载器的 `info.json` 不含播放量，所以播放量留空；`videoUrls`、封面链接等字段不会被当作本地媒体地址使用。

扫描也会为已有 Han1me 台账记录补齐 `info.json` 中缺少的标题、作者、上传日期和标签；只填空字段，不覆盖用户已有值，也不创建第二条记录。已有记录只有在找到真实 `info.json` 时才会补齐；新入账文件若无 JSON，标题和作者可按文件名/目录名推定并明确标注，上传日期、标签和播放量不猜测。

受令牌保护的接口：

- `GET /api/han1me/import`：读取导入器状态。
- `POST /api/han1me/import`：立即触发一次目录扫描；日常复制由后台轮询自动发现，不要求手动点击。
- `GET /api/status`：附带 `han1meImport` 状态。

接口先将完成复制且已稳定的文件加入播放台账，再排入单工作指纹队列；指纹仍未完成时可在电脑播放列表看到记录，手机同步会等待可用资料指纹，不会长期显示未匹配。新接收目录尚不存在时服务不会创建空视频文件；目录之后出现时后台轮询会继续发现。历史编号同步要求配置的 E、F 两个目录都可访问。
